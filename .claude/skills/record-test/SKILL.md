# record-test — 실측 결과 기록과 판정

## 1. 값 옮겨 적기
사진/메모에서 아래 항목을 읽어 `PROGRESS.md`의 "테스트 결과"에 **최신 항목을 위에** 추가한다.
읽을 수 없거나 빠진 값은 추측하지 말고 "판독 불가/미기재"로 적고 사용자에게 한 번에 모아서 묻는다.

```
### YYYY-MM-DD HH:MM — <기기: 테슬라 모델/폰> · <정차/주행> · 모드 <A|B|AB>
- 버전: p0-… / 설정: B 주기 …초, 고정밀 …, maximumAge …, timeout …
- 측정 시간: …분 / 화면 숨김: …회
| 항목 | A | B |
|---|---|---|
| 성공 / 에러 | | |
| 정확도 m (최소/중앙/최대) | | |
| 갱신 간격 s (최소/중앙/최대) | | |
| 위치 나이 s | | |
| 같은 timestamp 반복 | | |
| speed 값 있음 / 최대 km/h | | |
| heading 값 있음 | | |
| 응답시간 ms | | |
| 콜백 없음 / 늦은 콜백 | | |
- 사용자 메모: 권한 팝업 재등장 여부, 주행 중 브라우저 사용 가능 여부, 기타
- 판정: (아래 기준)
```

## 2. 판정 기준 (Phase 0 확인 항목)
| 확인 항목 | 통과 | 불확실 | 실패 |
|---|---|---|---|
| ① GPS 수준 정확도 | 정확도 중앙값 ≤ 30m, 주행 중 speed/heading 값이 대부분 있음 | 30~100m 또는 speed가 일부만 있음 | 중앙값 > 100m 또는 speed/heading 항상 null |
| ② 반복 요청 시 새 좌표 | 같은 timestamp 반복 ≤ 10%, 주행 중 갱신 간격 중앙값 ≤ 3초 | 반복 10~50% 또는 간격 3~10초 | 반복 > 50% 또는 간격이 10초 이상 자주 튐 |
| ③ 권한 팝업 재등장 | 첫 허용 후 다시 안 뜸 | — | 반복해서 뜸 |
| ④ 주행 중 사용 | 측정 끝까지 동작, 화면 숨김 없음 | 간헐적 끊김 | 주행 중 브라우저 사용 불가/정지 |

추가로 A와 B를 비교한다:
- A 단독이 잘 되면 → Phase 1은 watchPosition 사용
- A가 끊기고 B가 잘 되면 → getCurrentPosition 주기 호출 사용 (가설 B 지지). A+B 측정이 있으면 B가 A를 깨우는지도 판단
- 둘 다 실패 → Phase 1 진행 불가 판단 근거와 대안(예: 다른 위치 소스)을 정리해 사용자와 논의

판정은 숫자 근거와 함께 쓰고, 데이터가 부족하면 "판단 보류 — 필요한 추가 측정: …"으로 적는다. 낙관적으로 해석하지 않는다.
